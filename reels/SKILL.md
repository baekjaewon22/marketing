# 세븐스타즈 릴스 제작 가이드

이 문서 하나만 읽고 처음 보는 사람(또는 새 Claude 세션)이 작업을 이어갈 수 있게 쓴 문서다.
작업 흐름, 규칙, 디자인 기준, 이전에 겪은 문제와 해결법을 모두 담았다. 모든 작업은 **Opus 모델**로 한다.

목차
1. 프로젝트 개요와 결정 사항
2. 파일 구조
3. 환경 준비 (클라우드 / VS Code 로컬)
4. 주간 제작 절차 (금요일 루틴)
5. 대본 작성 규칙 (가장 중요)
6. 대본 JSON 스키마
7. 테마와 디자인 시스템
8. 렌더링 엔진 상세
9. 음원 (BGM·효과음)
10. 사진 (모자이크·순환)
11. 검증과 검수
12. 전달 (구글 드라이브 / 대체 경로)
13. 운영 작업 (정보 변경, 음원·사진·테마 추가, 단건 수정)
14. 이전에 겪은 문제와 해결법
15. 아직 정해지지 않은 것

## 1. 프로젝트 개요와 결정 사항

**브랜드:** SEVEN STARS (인스타 `@sevenstars_premium`, 신청 `sevenstars.kr`)
**상품:** 합정역 로테이션 소개팅. 합정역 도보 1분, 매주 토·일 오후 3시·6시, 약 2시간.
**실제 주소는 어디에도 쓰지 않는다**(운영자 결정 2026-10-22). 위치는 "합정역 1분 거리"(짧게는 "합정역 도보 1분")로만 쓴다. 검증기가 "서교동"·"394"를 막는다.
참가비 여 15,000원 · 남 30,000원 (정가 54,000원, 선착순 할인). 값은 바뀔 수 있으니 항상 `reels/brand-facts.json`을 기준으로 한다.

**진행 방식 (사실관계, 틀리면 안 됨):**
참석·첫인사 → 실명 대신 **"남자 1호"처럼 번호로** 불림 → 1:1로 **서로 얼굴을 보고** 마주 앉아 **10분** 대화 → 전 좌석 교차식으로 자리 이동 → 마음에 들면 쪽지 → 서로 고르면 연락처 교환. 약 2시간, 진행자가 분위기를 이끈다.
- 음료는 **커피 또는 티만, 주류 없음.** 술잔·술병이 보이는 사진·문구 금지(검증기·이미지 생성 프롬프트가 막음).
- 준비물: 신분증, 명함. 직업은 필수 확인. 현재 솔로만 참가(기혼·돌싱 불가). 참가자 70~80%가 혼자 온다.
- 예전 대본의 "5분마다 자리 이동", "닉네임으로 입장"은 틀린 정보였다(2026-10-22 전부 수정·재렌더). 검증기가 막는다.
- 운영자 소개글의 "만족도 높은", "재참여율", "커플 매칭 다수", "모집 마감", 외모·키 기준은 릴스에 쓰지 않는다(근거 없는 수치·주장, 차별적으로 보일 수 있음).
**가림막은 옆 테이블과의 사이만 가린다.** 상대 얼굴을 가리는 게 아니다. 예전에 "얼굴 안 보고 시작하는 소개팅", "가림막 너머 대화로 먼저", "얼굴 말고 대화에 집중" 같은 문구를 썼다가 사실과 달라 전부 고쳤다. 검증기가 이런 표현을 막는다.

**운영자가 정한 사항**
| 항목 | 결정 |
|---|---|
| 제작 주기 | 매주 금요일 12:00, 다음 날 토요일부터 그다음 금요일까지 7개 (2026-10-22 운영자 결정, 첫 실행 10/23 → 10/24~10/30) |
| 실행 방식 | B안: 대본부터 업로드까지 완전 자동, 결과만 알림 |
| 모델 | 모든 작업 Opus |
| 영상 규격 | 1080×1920 (9:16), 30fps, 15~21초, H.264 + AAC |
| 구조 | 훅(유입) → 안내 → 전환(신청). 마지막 장은 항상 신청 유도 |
| 톤 | AI 같은 말투 금지, 실제 20~30대 말투. 과한 홍보 금지(유입이 목적) |
| 후기 | 참가자 A님/B님 형식으로 지어서 써도 됨(운영자 승인). 실명·나이·수치 금지 |
| 사진 | 영상 하나에 사진 한 장, 요일마다 다른 사진으로 순환. 인물 얼굴은 전부 모자이크 |
| 음원 | `assets/audio/bgm/`에서 테마 분위기에 맞게 랜덤, 한 주 안에서는 중복 없이 |
| 브랜드 정보 | 매번 바뀔 수 있으니 확인을 받는 게 좋다(목요일 확인 루틴 + 금요일 알림에 사용값 표시) |
| 시즌 | 크리스마스면 눈 내리는 배경처럼, 문구와 배경 테마를 함께 바꾼다 |

## 2. 파일 구조

```
reels/
  SKILL.md              ← 이 문서
  PROMPTS.md            ← 상황별로 복사해 쓰는 프롬프트 모음
  ROUTINES.md           ← 예약(스케줄러) 등록 안내
  brand-facts.json      ← 장소·일정·가격·URL·금지 표현·허용 가격 (사실의 단일 출처)
  config.json           ← 드라이브 폴더, 주당 개수, fps, 요일별 기본 유형
  template.html         ← 대본 JSON + 테마 → 슬라이드 생성·애니메이션 엔진 (브라우저에서 동작)
  cine.html             ← 시네 쇼츠 엔진(컷·카메라 움직임·얼굴 가우시안·자막, 5-8)
  cine-refs.json        ← 시네 쇼츠 레퍼런스 6종(바이럴 포맷 기획)
  tools/gen-shots.js    ← 시네 컷 사진 생성(Codex, 앞 컷 이어 받기 + 얼굴 위치)
  tools/fetch-sfx.js    ← Openverse CC0 효과음 받기(9장)
  render.js             ← 대본 폴더 → 프레임 캡처 → MP4·캡션 txt·검수 시트
  validate.js           ← 대본 사실·형식 검증 (실패 시 exit 1)
  delivery-page.js      ← 드라이브 실패 시 Artifact로 올릴 주간 결과 페이지 생성
  tools/beats.py        ← 음원 BPM·첫 박 분석
  tools/mosaic.py       ← 사진 얼굴 모자이크 (격자 미리보기 → 박스 적용)
  samples/*.json        ← 대본 예시 (크리스마스, 미니멀)
  weeks/<시작일>/    ← 주차별 대본 7개 + DELIVERED(전달 완료 표시)
assets/
  audio/bgm/*.mp3 + manifest.json   ← BGM과 BPM·시작점·분위기·저작자
  images/sevenstars/*.jpg           ← 얼굴 모자이크 처리된 공간·인물 사진만
  fonts/Pretendard-*.ttf            ← 템플릿이 상대 경로로 직접 읽음
content/card-news/2026-10/sevenstars-reel-2026-10-20-hook{A,B,C}.mp4
                                    ← 첫 수작업 영상(훅 A/B/C 테스트용), 참고 자료
content/card-news/2026-10/sevenstars-animated-2026-10-20.html
                                    ← 엔진의 전신(단일 영상용). 지금은 reels/template.html을 쓴다
```
`.claude/` 폴더는 `.gitignore`에 있어 레포에 올라가지 않는다. 그래서 이 문서를 `reels/`에 둔다.
MP4 결과물은 레포에 커밋하지 않는다(`reels/out/`도 무시됨). 대본 JSON과 DELIVERED만 커밋한다.

## 3. 환경 준비

### 필요한 것
- Node.js 18+ 와 Playwright(Chromium)
- FFmpeg (`ffmpeg`, `ffprobe`)
- 도구 스크립트용 Python + `numpy`, `opencv-python-headless` (음원 분석·모자이크할 때만)

### 클라우드 세션 (Claude Code on the web / 예약 실행)
이미 설치돼 있다. Chromium은 `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`, Playwright는 `/opt/node-tools/node_modules/playwright`(render.js가 자동으로 찾음).
시스템 `python3`에는 numpy가 없고 PIL도 깨져 있다. numpy·cv2가 있는 건 `python3.13`이다.

### VS Code 로컬 (Windows/macOS)
```bash
git clone https://github.com/baekjaewon22/marketing && cd marketing
npm i playwright && npx playwright install chromium
# FFmpeg 설치: Windows는 winget install ffmpeg, macOS는 brew install ffmpeg
pip install numpy opencv-python-headless   # 도구 쓸 때만
node reels/validate.js reels/samples        # OK 2줄이면 준비 끝
node reels/render.js reels/samples ./reels/out/test --fps 5 --jobs 1   # 시험 렌더링
```
- 로컬에서는 render.js의 `CHROME` 경로가 없으니 Playwright 기본 Chromium을 쓴다(자동).
- 이모지 폰트는 리눅스의 Noto Color Emoji를 먼저 찾고, 없으면 OS 이모지(Windows Segoe, Apple)로 나온다. 모양이 조금 다를 수 있다.
- 한글 폰트는 `assets/fonts/`의 Pretendard를 상대 경로로 읽으므로 설치할 필요가 없다.
- Windows: winget으로 설치한 ffmpeg는 `%LOCALAPPDATA%\Microsoft\WinGet\Links`에 있다. 설치 직후 열려 있던 터미널·VS Code·예약 작업은 PATH에 없을 수 있으니 이 경로를 PATH에 붙여서 실행한다.
- 생성 사진을 쓰려면 Codex CLI: `npm i -g @openai/codex` (로그인은 Codex 데스크톱 앱과 공유).
- `npm i playwright`로 생기는 `package.json`·`node_modules/`는 `.gitignore`에 있다(PC마다 따로 설치).
- 운영 PC(Windows, 상시 켜짐) 경로: 저장소 `C:\Users\260209\git\sevens shorts\marketing`.

## 4. 주간 제작 절차 (금요일 루틴)

시간 예산: 대본 10분 + 2fps 검수 렌더 5분 + 30fps 본 렌더 약 60~70분(7개, jobs 3 기준) + 업로드.

### 4-0. 준비
```bash
git pull origin master
node reels/validate.js reels/samples   # 환경 확인
```
목요일 확인(4-11)의 `reels/out/brand-check.json`이 있으면 `slack_read_thread`로 그 스레드의 답글을 읽는다. 운영자가 바뀐 정보를 적었으면 13장대로 `brand-facts.json`을 고치고(가격이면 `allowed_prices`도) 커밋한 뒤 진행한다. 답글이 없거나 "맞아요"면 그대로 진행.

### 4-1. 대상 주와 중복 확인
- 실행일(금) 기준 **다음 날 토요일부터 그다음 금요일까지 7일**. 시작 토요일 날짜가 폴더 이름이 된다 (예: 10/30 실행 → `reels/weeks/2026-10-31/`, 10/31~11/6). 예약 실행은 프롬프트에 대상 기간을 직접 적어 준다.
- 2026-10-26·11-02·11-09 폴더는 예전 월~일 기준으로 미리 만든 것이다(운영자가 이미 사용). 기간이 겹쳐도 새 기간은 새로 만든다. 반복 회피용으로만 읽는다.
- `reels/weeks/<시작일>/DELIVERED`가 있으면 이미 전달한 주다. **아무것도 만들지 말고** "이미 제작된 주라 건너뜀" 알림만 보내고 끝낸다.
- 그 주 폴더에 대본은 있는데 DELIVERED가 없으면 이전 실행이 중간에 끊긴 것이다. 새로 쓰지 말고 있는 대본·생성 사진·`reels/out` 렌더 결과를 이어서 쓰고 남은 단계부터 진행한다.
- 직전 2주의 `reels/weeks/` 대본을 읽어 테마·훅·컨셉이 반복되지 않게 한다.

### 4-2. 테마 정하기 (7일) — 선택 도구로 무작위, 반복 없이
```bash
node reels/tools/pick-themes.js <시작일>   # 테마 + 시네 요일(화·일)의 레퍼런스(ref)
```
- 출력된 날짜별 테마를 그대로 쓴다(시작일로 시드를 정한 무작위라 다시 돌려도 같다). 테마는 36개(`reels/themes.json`, 7장).
- 도구가 지키는 규칙: 시즌 기간(크리스마스 12/1~25 3개, 새해 12/26~1/7 3개, 겨울 12~2월 1개, 발렌타인·화이트데이 2개, 봄·여름 3개, 가을 9/15~11/30 2개)에 든 날에 그 시즌 변형 테마를 넣고, 나머지는 기본 테마 13개에서 고른다. **같은 주 안에서 같은 테마 없음**, 직전 14일 대본에 쓴 테마는 피함, 밝은 테마 최대 2개, 12/24·25는 크리스마스 계열, 12/31·1/1은 새해 계열.
- 대본 내용(시즌 문구)이 테마와 어울리게 쓴다. 예: `xmas-red` 날은 연말·크리스마스 문구, `summer-rain` 날은 비 오는 주말 문구. 정말 안 맞으면 그 날만 같은 시즌의 다른 테마로 바꿔도 되지만 주 안 중복은 안 된다.
- **할로윈(10월 말) 파티 콘셉트는 쓰지 않는다.** 10·29 참사 이후 국내 정서를 고려한 결정이다. 10/29 전후는 차분한 톤.
- Google Calendar 커넥터가 있으면 공휴일·기념일을 확인한다(없으면 위 표대로).

### 4-3. 성과 반영 (가능할 때만)
Supermetrics 커넥터가 있으면 `sevenstars-marketing-check` 스킬 방식으로 지난 2주 릴스 성과(조회·저장·공유·프로필 방문)를 보고, 반응 좋은 훅 유형을 이번 주에 1~2개 더 배치한다. 없으면 건너뛴다(실패 아님).

### 4-3b. 테마별 생성 사진 (Codex, 대본 작성 뒤 4-5 검증 전에)
```bash
node reels/tools/gen-images.js --week reels/weeks/<시작일>
```
- 대본마다 그 테마의 색감·조명(`themes.json` tone)으로 공간 사진 1장을 만들고 대본에 `"ai_photo"`를 적는다. 장면 14종이 주마다 다른 순서로 돌아 주 안에서는 겹치지 않는다. 7장에 10~15분.
- 만든 사진을 **한 장씩 Read로 열어** 검수한다(10장 '생성 사진'). 불량이면 그 파일을 지우고 대본의 `ai_photo` 줄도 지운 뒤 다시 실행하면 그 대본만 새로 만든다(이미 있는 것은 건너뜀).
- 실패한 대본은 `ai_photo` 없이 실제 사진(테마 색으로 물든 그라데이션)으로 렌더된다. 실패 아님, 알림에 적는다.

### 4-3c. 시네 쇼츠 컷 사진 (Codex, 시네 대본 작성 뒤 4-5 검증 전에)
```bash
node reels/tools/gen-shots.js --week reels/weeks/<시작일>
```
- 시네 대본(화·일)마다 컷 5~6장을 만든다. 컷마다 앞 컷을 참고로 넣어 인물·옷·빛이 이어진다. 두 대본을 동시에 만들어 20~40분.
- 만든 컷을 **한 장씩 Read로 열어** 검수한다(10장 '생성 사진' 기준 + 앞 컷과 이어지는지). 불량 컷은 `--only <파일>.json --redo 3,5`(0부터 센 컷 번호)로 다시 만든다.
- Codex가 적은 `faces`(얼굴 위치)를 확인한다. 얼굴이 보이는데 빠졌으면 `[x, y, w, h]`(0~1 비율)를 직접 넣는다. 그 자리는 렌더 때 자연스러운 가우시안으로 흐려진다.
- gen-images.js(4-3b)는 시네 대본을 건너뛴다(ai_photo 대신 컷 사진을 씀).

### 4-4. 대본 7개 작성
요일별 기본 유형 (`reels/config.json`의 `weekday_plan`):
| 요일 | 유형 | 권장 구성 |
|---|---|---|
| 월 | 공감형 훅 | hook-rows → cover → info → cta |
| 화 | **시네 쇼츠** (진행 방식을 브이로그로) | `format: "cine"`, 5-8 참고 |
| 수 | 참가자 후기 | hook-statement → reviews → quote → info → cta |
| 목 | 자주 묻는 질문 | hook-statement → steps(질문형) → info → cta |
| 금 | **취소석 무료체험단 초청 (매주 필수, 전환 유도형)** | hook → cover → steps(신청 방법) → quote → cta. 5-7 참고 |
| 토 | 가격 혜택 | hook-rows(가격 행) → info → quote → cta |
| 일 | **시네 쇼츠** (공간·분위기, 공간 투어) | `format: "cine"`, ref는 `walk-in`처럼 venue 컷만. 5-8 참고 |
시네 쇼츠 요일은 `config.json`의 `cine_days`(화·일, 운영자 요청 2026-10-29 "반복적이지 않은 바이럴용 실사 느낌 쇼츠 주 2회"). 나머지 5개는 슬라이드형.
금요일 초청 영상은 매주 반드시 1개 만든다(운영자 결정 2026-10-22). 시즌 주제는 다른 요일(월 공감형·일 공간 등)에 녹인다. 시즌 주간(크리스마스 등)은 금요일을 뺀 2~3개를 시즌 주제로 바꿔도 된다. 같은 구성만 반복하지 말고 매주 조금씩 바꾼다.

파일 이름: `reels/weeks/<시작일>/YYYY-MM-DD_요일_컨셉.json` (컨셉은 띄어쓰기 없이). 이 이름이 그대로 MP4·txt 이름이 된다.
작성 규칙은 5장, 형식은 6장. 실제 예시는 `reels/weeks/2026-10-26/`(첫 주차)과 `reels/samples/`.

### 4-5. 검증
```bash
node reels/validate.js reels/weeks/<시작일>
```
FAIL이 하나라도 있으면 고쳐서 다시. 통과 전에는 렌더링하지 않는다.

### 4-6. 빠른 검수 렌더 (2fps)
```bash
node reels/render.js reels/weeks/<시작일> /tmp/reels-qa/<시작일> --fps 2 --jobs 3
```
- 출력 줄마다 `길이(초) 음원 사진`이 나온다. 확인할 것: 길이 15~21초, 같은 음원 반복 없음, 사진 7일 모두 다름(사진이 6장이면 1장만 겹침), 비시즌인데 캐럴이 뽑히지 않았는지.
- `QA 경고`가 있으면 그 슬라이드 문구를 줄인다.
- `*_contact.jpg`(슬라이드별 완성 화면)를 **전부 Read 도구로 열어서** 11장의 체크리스트대로 본다.

### 4-7. 본 렌더 (30fps)
```bash
node reels/render.js reels/weeks/<시작일> /tmp/reels-out/<시작일> --fps 30 --jobs 3
```
- 60~70분 걸린다. 백그라운드로 돌리고 끝날 때까지 기다린다(중간에 프레임 폴더 `/tmp/reel-*`의 파일 수로 진행률 확인 가능).
- 한 개만 다시: `--only YYYY-MM-DD_요일_컨셉.json` (여러 개는 쉼표로). `--only`로 돌려도 음원·사진은 전체 렌더와 같다.
- 결과: `<이름>.mp4`, `<이름>.txt`(캡션·해시태그·음원 출처), `<이름>_contact.jpg`, `render-report.json`.
- **로컬 예약 실행(Windows, `claude -p`)에서는 백그라운드 실행(run_in_background)을 절대 쓰지 않는다.** 응답을 마치면 프로세스가 끝나서 백그라운드 작업 결과를 받지 못한다(2026-10-22 시험에서 검수 렌더를 백그라운드로 돌리고 끝나 영상이 안 나옴). `run-weekly.ps1`은 DELIVERED가 없으면 `--continue`로 최대 3번 이어서 시킨다.
- 명령 하나가 10분을 넘기면 끊기므로, 7개를 한 번에 돌리지 말고 파일마다 `--only`로 하나씩 foreground로 돌린다(timeout 600000, 한 개 4~5분):
  `node reels/render.js reels/weeks/<시작일> reels/out/<시작일> --fps 30 --jobs 1 --only <파일>.json`
  끝나면 `*_contact.jpg` 7장을 다시 Read로 보고, 문제가 있으면 대본을 고쳐 그 파일만 다시 렌더한다.

### 4-8. 전달 → 12장
로컬 예약 실행: `node reels/deliver-local.js reels/weeks/<시작일> reels/out/<시작일>` (MP4·txt 14개 복사·확인 + DELIVERED 기록. FAIL이면 12장 2번). 성공하면 **완성본만 남기고 작업 파일을 지운다**: 렌더 폴더의 MP4·검수 시트, qa 폴더, 그 주 생성 사진(ai_photo·시네 컷), 흐린 사진 캐시. 대본 JSON의 사진 경로도 지운다(운영자 결정 2026-10-29). 그래서 생성 사진은 커밋하지 않는다(4-9의 `git add -A`는 지운 것을 그대로 기록).
### 4-9. 기록
```bash
echo "<드라이브 폴더 링크 또는 아티팩트 링크>" > reels/weeks/<시작일>/DELIVERED   # deliver-local.js를 썼으면 이미 있음
```

- 실패·경고가 있었다면 무엇이 왜

## 5. 대본 작성 규칙 (가장 중요)

### 5-1. 구조: 유입 → 안내 → 전환
- **훅(첫 장):** 스크롤을 멈추게 하는 한 장. 홍보처럼 보이면 넘긴다. 공감·질문·반전으로 시작한다.
- **안내(2~4장):** 진행 방식, 일정·장소·가격, 후기, 공간. 사실은 brand-facts에서 자동으로 채워진다.
- **전환(마지막 장, 항상 `cta`):** 댓글로 유도한다(운영자 결정 2026-10-22). 일반 영상은 "댓글 주시면 신청 링크 보내드려요"(cta `sub` 기본값), 초청 영상은 "댓글 주시면 무료초청 링크 드려요". sevenstars.kr 버튼은 고정. 부담 없는 초대. "신청하세요!"가 아니라 "한번 와볼래요?"의 온도.
- 슬라이드 총 4~7장. 영상 길이 15~21초.

### 5-2. 훅 유형 (매주 섞어 쓴다)
| 유형 | 예시 (실제 사용) |
|---|---|
| 공감형 | "소개팅 자꾸 미루게 되는 이유" / "이번 가을도 그냥 지나갈 것 같아요?" |
| 호기심형 | "하루에 여러 명, 1:1로 만나는 소개팅" (태그: "합정역에 이런 곳이 있어요") |
| 질문형 | "소개팅 앱, 또 결제했어요?" (태그: "이번 달만 몇 번째예요?") |
| 후기형 | "혼자 갔는데 생각보다 괜찮았어요" |
| FAQ형 | "가기 전에 이것만 확인해요" |
| 가격형 | "앱 결제 대신 주말 2시간" |
| 공간형 | "조명부터 분위기가 달라요" |
| 시즌형 | "크리스마스, 또 혼자 보낼 거예요?" |

`hook-rows`의 행은 **문제 → 해결** 짝이다. 문제는 사람들이 실제로 망설이는 이유, 해결은 사실에 근거한 짧은 답.
좋은 행 예시: 😮‍💨 "옆에서 다 들릴까 봐" → "테이블마다 가림막" / 🙋 "혼자 가면 뻘쭘할까 봐" → "다들 혼자 와요" / ⏰ "주말 하루 다 쓰긴 싫고" → "딱 2시간" / 💸 "앱 결제는 끝이 없고" → "1회 15,000원~"

### 5-3. 말투
- 실제 20~30대가 쓰는 반말 섞인 존댓말. 짧게. 한 줄 18자 안쪽.
- **쓰지 말 것:** "지금 바로", "놓치지 마세요", "망설이지 마세요", "특별한 경험", "완벽한", "최고의", "~해보세요!" 남발, 느낌표, ✓ 장식, 💪🔥👇 같은 강조 이모지, 문장마다 이모지.
- 이모지는 `hook-rows` 행 아이콘에만 쓴다. 이모지는 반드시 완성형(변형 선택자 포함)으로: `🍽️`(O) `🍽`(X, 글자 모양으로 깨짐).

문구 수정 실제 사례 (전 → 후)
| 전 (AI 같음/사실 오류) | 후 |
|---|---|
| 소개팅을 못 하는 이유 | 소개팅 자꾸 미루게 되는 이유 |
| 외모에 자신 없어서 → 가림막 있어요 ✓ | 옆에서 다 들릴까 봐 → 테이블마다 가림막 |
| 👇 이게 다 가능한 소개팅이 있어요 | 그래서, 이런 소개팅은 어때요? |
| 지금 바로 신청하세요! | 이번 주말, 한번 와볼래요? |
| 🔥 선착순 마감! | 회차마다 자리가 정해져 있어요 |
| 망설이지 마세요 💪 나도 해봤어요! | 처음 오는 분이 대부분이에요 |
| ⭐⭐⭐⭐⭐ 만족도 4.8 / 5 | (삭제: 근거 없는 수치) |
| 가림막 너머, 대화로 먼저 만나요 | 테이블마다 가림막, 둘만의 대화 |
| 얼굴 말고 대화에 집중 | 옆 테이블은 가림막으로 분리 |

### 5-4. 사실
- 장소·일정·가격·URL은 대본에 직접 쓰지 말고 `info`/`cta`/`cover`가 brand-facts에서 자동으로 채우게 둔다.
- 문구에 가격을 쓸 땐 brand-facts의 `allowed_prices` 값만 (검증기가 다른 금액을 막음).
- 만족도·매칭률·"100%"·"무료" 같은 수치·주장 금지. 단 운영자가 실제로 여는 **무료체험** 초청은 `allowed_phrases`로 허용된다(조건은 "DM으로 안내"로 둔다). "실제로" 같은 단정도 피한다.
- 사진으로 보이는 사실(우드톤 공간, 테이블 조명)은 써도 된다.

### 5-5. 후기
`reviews`의 `who`는 "참가자 A님", "참가자 B님" 형식. 문장은 짧고 구체적인 경험담 한두 줄. 진행 방식 사실과 맞아야 한다(얼굴 안 봤다는 식 금지).
예: "처음엔 긴장했는데 10분씩이라 오히려 편했어요" / "옆자리가 가려져 있으니까 대화에만 집중할 수 있었어요" / "혼자 가서 걱정했는데 다들 혼자라 금방 편해졌어요"

### 5-7. 취소석 무료체험단 초청 영상 (금요일, 매주 1개)
목적은 유입이 아니라 **전환**: 보는 사람이 댓글을 남기게 한다. 댓글을 주면 **무료초청 링크**를 보낸다(brand-facts `invite`, 초청 링크는 운영자가 따로 관리).
- 훅: 취소석이 생겨 무료체험단으로 초대한다는 사실을 첫 장에 바로. 예: "이번 주 취소석, / 무료체험으로 초대해요", "로테이션 소개팅 / 무료체험 해볼래요?". 자리 수는 운영자가 말해 준 주에만 쓴다(예: "여성 1자리").
- 가운데: `cover`(장소·일정만 나옴) + `steps` 신청 방법(댓글 남기기 → 무료초청 링크 받기 → 주말에 참석, 신분증·명함) + `quote`(10분 1:1, 커피·티).
- **가격 카드가 나오는 `info`는 쓰지 않는다**(무료 체험과 가격이 함께 보이면 헷갈림).
- `cta`: `title`은 "댓글 주시면 / 무료초청 링크 드려요" 계열, `sub`는 "현재 솔로인 분만 참가할 수 있어요".
- 캡션 마지막 줄: "댓글 주시면 무료초청 링크를 보내드려요." 해시태그에 `무료체험단`, `취소석`.
- "무료"는 금지 표현이지만 "무료체험"·"무료 체험"·"무료초청"만 `allowed_phrases`로 허용된다. "무료로" 같은 다른 형태는 검증기가 막으니 "무료체험으로"처럼 쓴다.
- 매주 같은 문장을 반복하지 말고 훅 유형(공감형·질문형·후기형)을 바꿔 가며 쓴다. 예시: `reels/specials/2026-10-22/`, `reels/weeks/2026-10-26/2026-10-30_금_*`.

### 5-8. 시네 쇼츠 (화·일, 주 2회) — 바이럴용 실사 느낌
목적: 슬라이드형이 반복적이라는 운영자 피드백(2026-10-29). **실제로 찍은 브이로그처럼 보이는** 12~20초 영상으로 유입을 노린다. 엔진은 `reels/cine.html`, 레퍼런스는 `reels/cine-refs.json`.
- **레퍼런스 고르기:** pick-themes.js가 화·일에 적어 주는 `시네:<ref>`를 그대로 쓴다(직전 28일 안 쓴 것, 일요일은 공간 ref 3종 walk-in·candle-detail·before-open 중). 참고: `refs` 8종(POV 토요일 저녁 / 10분마다 새로운 사람 / 폰 내려놓고 대화 / 공간 투어 / 처음이라 걱정되는 3가지 / 시즌 스토리) 중 직전 4주에 안 쓴 것. `fits`가 있는 ref(`walk-in`)는 그 컨셉 날(일요일 공간)에만. 일요일은 venue 컷만 쓰는 ref로 한다(우리 공간 영상은 실제 공간 기반).
- **그대로 베끼지 않는다:** ref의 shots는 뼈대. scene은 그 주 테마·계절에 맞게, text·hook은 새로 쓴다. 훅은 `hooks` 예시 계열(POV·질문형·숫자형)로.
- **컷 구성:** 4~7컷(보통 5~6). 첫 컷은 자막 없이 훅이 덮는다. 자막은 한 줄 18자 이하, 컷마다 한 문장. 자막은 글자마다 튀어 오르는 타이포 효과로 나오고, `*강조*`로 감싼 말(없으면 숫자 표현 1분·70~80%·10분 자동)은 금색 + 형광펜 바로 강조된다. 컷마다 강조어 하나. 사실은 5-4와 같다(10분 1:1, 번호로 부름, 커피·티, 혼자 70~80%, 신분증·명함, 합정역 걸어서 1분).
- **카메라:** 컷마다 `motion`(push·pull·pan-l·pan-r·tilt-up·handheld·rack)과 `cut`(hard·whip·flash·dip). hard를 기본으로, whip·flash는 영상당 1~2번(효과음이 붙음), 마지막 컷은 dip. 모든 컷에 손떨림·24fps 질감·노출 떨림·필름 그레인이 자동으로 들어간다.
- **사람:** AI 인물 OK(운영자 승인). 얼굴은 초점 밖·옆·뒤·손 위주로 만들고, 보이는 얼굴은 `faces`에 적어 **가우시안으로 자연스럽게 흐린다**(모자이크 대신, 얕은 심도로 초점이 나간 것처럼). `focus: [x, y]`를 주면 그 점만 또렷하고 주변이 흐려진다(rack이면 흐렸다가 초점이 들어옴).
- **`stamp`:** 캠코더 시각 표시(예: "SAT 17:21"). 영상당 0~1번, 첫 컷에.
- **cta:** 마지막에 그 컷이 흐려지며 브랜드·제목·sevenstars.kr·"댓글 주시면 신청 링크 보내드려요". `cta.title` 2줄.
- **소리:** 박자감 있는 곡(upbeat 우선) + 휩·플래시 컷에 whoosh + cta에 chime + 카페 웅성거림(ambience)을 아주 작게.
- 캡션·해시태그는 5-6과 같고 `소개팅브이로그` 같은 브이로그 태그를 하나 넣는다.

### 5-6. 캡션 (`caption`)과 해시태그
- 3줄 이내. 1줄: 공감 또는 상황, 2줄: 무엇인지(합정역 도보 1분, 1:1, 토·일), 3줄: "댓글 주시면 신청 링크 보내드려요." (금요일 초청 영상은 "댓글 주시면 무료초청 링크를 보내드려요.")
- 해시태그 4~6개: `세븐스타즈`, `로테이션소개팅`, `합정역소개팅` 고정 + 주제 태그 1~3개.
- 음원 출처는 render.js가 txt 맨 아래에 자동으로 붙인다.

## 8. 렌더링 엔진 상세 (`template.html` + `render.js`)

**박자 동기화**
- 곡 BPM으로 박 길이(BEAT)를 구하고, 슬라이드 한 장 길이(STEP)는 **4·6·8박 중 2.55초 이상이 되는 가장 짧은 것**. (예: 85BPM→4박 2.8초, 124BPM→6박 2.9초, 153BPM→8박 3.1초)
- 슬라이드 i는 `T_ON[i] = i × STEP`에 정확히 박 위에서 바뀐다. 전환(디졸브 600ms)은 그 박을 가운데에 두고 일어난다.
- 마지막 cta는 STEP + 꼬리(약 1.4초, 박 단위)만큼 더 보여 준다.
- 글자 등장 시점(`data-t`의 delay)은 그 슬라이드 길이의 60% 안에 들어오도록 압축한 뒤, 반 박(요소가 많으면 1/4박) 격자에 맞춘다. 같은 칸이면 다음 칸으로 밀어 순서를 지킨다.
- BGM은 manifest의 `start`(첫 박)부터 잘라 쓰므로 영상 0초 = 박.

**애니메이션 종류** (`data-t="delay,dur,type"`): 0 페이드, 1 아래에서 올라오며 페이드, 5 튕기듯 커지기, 6 왼쪽→오른쪽 글자 드러내기(clip).
**전환:** 다음 슬라이드가 오른쪽 60px에서 들어오며 1.035배→1배, 이전 슬라이드는 왼쪽으로 빠지며 살짝 축소.
**사진 움직임:** 켄 번즈(천천히 확대·이동) + 박마다 아주 작은 확대 펄스.
**자동 글자 축소(fit):** `.fit` 요소의 원래 폭(width:max-content로 측정)이 칸보다 넓으면 4%씩 줄인다.
**QA:** 각 슬라이드가 다 나타난 시점에 모든 글자 요소가 안전 영역(가로 30~1050, 세로 150~1700) 밖이면 경고.

**render.js 흐름 (영상 1개)**
1. 곡 선택(9장) · 사진 선택(10장)
2. Playwright로 `template.html` 열기 (대본·brand-facts·BPM을 `addInitScript`로 주입, `?script=` 없이)
3. `window.ready` 대기(사진 decode, 폰트 로드, fit, 박자 계산) → `window.qa()` → 슬라이드별 완성 화면 캡처(검수 시트)
4. `seekTo(ms)`로 프레임마다 화면 고정 후 PNG 캡처 (애니메이션을 실시간 재생하지 않으므로 끊김 없음)
5. FFmpeg: PNG → H.264(crf 19, yuv420p, faststart) + BGM(loudnorm -15 LUFS, 페이드인 0.4초·아웃 1.8초) + 전환 효과음 + 리미터
6. 캡션 txt, 검수 시트 jpg 저장, 프레임 폴더 삭제

## 9. 음원

`assets/audio/bgm/manifest.json` 항목: `file`, `bpm`, `start`(본 구간 첫 박, 초), `mood`(배열), `title`, `artist`.
- mood: `calm`, `upbeat`, `christmas`, `vocal`(가사 있음 - 글자 읽기를 방해할 수 있음).
- **캐럴(Christmas Chores)은 mood가 `christmas`만** → 크리스마스 테마에서만 뽑힌다. 뮤직박스류는 `calm`/`upbeat` + `christmas`를 함께 달아 겨울에도 쓴다.
- 선택: 테마의 분위기 목록과 겹치는 곡 중에서, **그 주에 아직 안 쓴 곡**이면서 **직전 7일 렌더(reels/out/*/render-report.json)에 쓰지 않은 곡**을 날짜·컨셉 해시로 고른다. 후보가 없으면 조건을 하나씩 푼다.

**효과음 (`assets/audio/sfx/`, `manifest.json`)**
- 출처: Openverse API(무료, 키 없음)에서 **CC0만** 받은 Freesound 녹음. 상업 홍보물이라 `by`·`nc` 라이선스는 쓰지 않는다. CC0라 캡션 출처 표기 불필요(manifest에 제목·작가·원본 링크는 남김).
- 분류: `whoosh`(슬라이드 전환) · `chime`(마지막 cta 등장) · `sparkle`(크리스마스·새해 시즌 테마의 cta) · `pop`(대본에서 지정할 때만).
- 선택: 영상마다 전환음 1개·cta음 1개를 날짜·컨셉 해시로, 그 주에 되도록 겹치지 않게. 대본에서 `"sfx": {"transition": "whoosh/....wav", "cta": "chime/....wav"}`로 지정 가능. 라이브러리가 비면 예전 합성 스우시(0.5초 핑크노이즈)로 돌아간다.
- 박자 맞춤: manifest의 `peak`(소리가 가장 큰 시각)를 슬라이드 등장 박에 맞춰 그만큼 앞에서 시작. 볼륨 전환 0.35, cta 0.3.
- 늘리기: `node reels/tools/fetch-sfx.js --per 10` (이미 받은 건 건너뜀, 분류별 10개까지). 제목 필터(`need`/`DENY`)에 안 맞는 소리는 받지 않고, 필터를 고친 뒤 다시 돌리면 기존 것도 지운다. 받은 소리는 앞 무음 제거·길이 제한·피크 -3dB로 다듬어 48k wav로 저장.
- 새로 받은 소리는 한 번 들어 보고(분위기에 안 맞으면 파일과 manifest 항목 삭제) 커밋한다.

## 10. 사진

- 위치: `assets/images/sevenstars/` — 실제 사진은 **얼굴 모자이크 처리본만**. 원본은 레포에 절대 올리지 않는다.
- 실제 사진 6장: `venue-wide`(넓은 홀), `venue-closeup`(가림막 테이블 근접), `venue-bright`(밝은 홀), `venue-candle`(캔들 조명), `couple-closeup`(남녀 클로즈업, 세로), `couple-table`(테이블 마주 앉은 남녀, 가로).
- `couple-closeup`·`couple-table`은 모자이크 얼굴이 커서 글자 뒤에서 지저분해 보이므로 **자동 배정에서 뺐다**(render.js `MANUAL_ONLY`). 대본에서 `photo`로 지정할 때만 쓴다.
- Codex 생성 사진: `assets/images/sevenstars/ai/YYYYMMDD-장면.jpg` (1080×1920). 실제 사진을 참고로 만든 공간 컷이라 얼굴이 없다(아래 '생성 사진').
- **영상 하나 = 사진 1~2장.** 사진 슬라이드가 2개 이상이면 2장, 아니면 1장. 사진 슬라이드들이 그 사진을 번갈아 다른 구도·움직임으로 보여 준다.
- 순환: 생성 사진과 실제 사진을 번갈아 섞은 목록을 그 주 전체에 대해 한 번에 배정한다(2장짜리 영상은 보통 생성 1장 + 실제 1장). 주번호는 그 주 첫 대본 날짜로 한 번만 계산(날짜마다 계산하면 순서가 어긋남 - 실제로 겪은 버그). `--only`로 다시 렌더해도 전체 렌더 때와 같은 사진·음원이 나온다. 한 영상에 사진을 지정(`photo`·`photos`)해도 다른 영상의 배정은 밀리지 않고, 지정된 사진과 겹치는 영상만 안 쓴 사진으로 바뀐다.
- 가로 사진은 9:16으로 잘리므로 `template.html`의 `FOCUS`에 초점 좌표(%)를 넣는다 (예: `couple-table.jpg: [42,50]`).

생성 사진 (Codex)
- 주간: `node reels/tools/gen-images.js --week reels/weeks/<시작일>` (4-3b). 수동: `node reels/tools/gen-images.js <장수> [--scenes hands,candle]`. 1080×1920 JPG로 `ai/`에 저장, 한 장에 1~2분.
- 장면은 두 종류를 섞는다(운영자 결정 2026-10-22).
  - **공간 장면 14종**(table·partition·candle·hall·notes·chairs·light·hands·cups·aisle·corner·overhead·bokeh·pen): 실제 공간 사진을 참고로 붙여 **우리 공간 그대로**. 시즌 장식처럼 실제로 없는 것은 그리지 않는다(5-4).
  - **감성 장면 10종**(talk·coffee-people·note-pass·citynight·walk·window·ready·street-season·laugh·phone-down): 공간 밖이어도 되고 AI 인물이 나와도 된다. 계절 거리 장식도 자연스럽게 허용.
  - 한 주에 감성 장면 4개 안팎, 나머지는 공간 장면. **공간·분위기 영상(일요일 등 '우리 공간'을 보여 주는 영상)은 공간 장면만** 쓴다. 다른 곳 사진을 우리 공간처럼 보이면 안 된다.
- 색감: 그 대본 테마의 `tone`(themes.json)을 한눈에 느껴질 만큼 분명하게. 퀄리티: 매거진 화보, 35mm·얕은 심도·필름 그레인, AI 같은 매끈함 없이.
- 인물: AI 인물이라 초상권 문제는 없지만, 얼굴 정면 클로즈업은 피하게 만든다(옆·뒷모습·초점 밖·화면 일부). 검수 때 **얼굴이 정면으로 또렷하면 mosaic.py로 가린다**(아래 '새 사진 추가' 2~3단계를 생성 사진에 그대로).
- 만든 뒤 **한 장씩 Read로 열어** 글자·로고, 술(잔·병), 뭉개진 손·물건, 공간 장면인데 실제 공간과 너무 다른 것이 있으면 그 파일을 지우고 대본의 `ai_photo`도 지운 뒤 다시 실행한다. 남은 것만 커밋.
- 테마 이름이 들어간 생성 사진(`<날짜>-<테마>-<장면>.jpg`)은 그 대본에서만 쓰이고 자동 순환에는 들어가지 않는다(다른 테마와 색이 안 맞음). Codex가 실패해도 실제 사진만으로 계속 진행한다(실패 아님, 알림에 적음).
- 필요: `npm i -g @openai/codex` + Codex 로그인(`~/.codex/auth.json`, Codex 데스크톱 앱과 공유).

새 사진 추가 (얼굴 모자이크 필수)
1. `python3.13 reels/tools/mosaic.py grid <원본> /tmp/grid.jpg` → Read로 열어 **모든 사람**(뒷모습·옆모습·멀리 있는 사람 포함)의 머리 좌표를 읽는다
2. `python3.13 reels/tools/mosaic.py apply <원본> assets/images/sevenstars/<이름>.jpg '[[x,y,w,h],...]' ['[x1,y1,x2,y2]']` (테두리 프레임이 있으면 crop)
3. 결과를 Read로 열어 하나라도 얼굴이 보이면 박스를 넓혀 다시
4. 가로 사진이면 FOCUS 추가, 2fps 렌더로 구도 확인, 커밋

## 11. 검증과 검수

**validate.js가 막는 것:** 필수 키 누락, 알 수 없는 테마·타입, 슬라이드 4~7장 아님, 첫 장이 훅이 아님, 마지막이 cta 아님, rows/steps/reviews 개수, 제목 4줄 이상, brand-facts의 `banned_claims`(얼굴 안 보·얼굴 말고·가림막 너머·블라인드 소개팅·만족도·매칭률·100%·무료 등), 허용되지 않은 가격, 느낌표 연속.

**검수 시트(`*_contact.jpg`)를 눈으로 볼 때 체크리스트**
- [ ] 글자 잘림·겹침·화면 밖 없음, 자동 축소로 너무 작아진 글자 없음
- [ ] 이모지가 깨진 모양(네모·글자형)으로 나오지 않음
- [ ] 사실 오류 없음(특히 가림막·얼굴 관련), 오탈자 없음
- [ ] 마지막 장에 sevenstars.kr, 댓글 유도 문구(일반: 신청 링크 / 초청: 무료초청 링크), 장소·일정 한 줄이 모두 보임
- [ ] 테마와 문구가 어울림(가을 문구에 크리스마스 테마 같은 불일치 없음)
- [ ] 사진 위 글자 가독성 충분, 모자이크된 얼굴이 글자 바로 뒤에서 지저분해 보이지 않음
- [ ] 영상 길이 15~21초, 같은 주에 같은 사진·음원 반복 최소

문제가 있으면 대본을 고치고 그 파일만 `--only`로 다시 렌더링한다.

**기본: 구글 드라이브** (`reels/config.json`의 `drive_root_folder_url`이 있으면 그 폴더 아래, 없으면 `세븐스타즈 릴스` 폴더를 찾거나 만듦)

**대체: Artifact 페이지** (드라이브 도구가 없거나 업로드 실패 시)
```bash
cp -r /tmp/reels-out/<시작일> <스크래치패드>/delivery-<시작일>
node reels/delivery-page.js reels/weeks/<시작일> <스크래치패드>/delivery-<시작일>
```
출력된 `delivery.html`을 `file_path`로, `videos/<날짜>.mp4` 7개를 `files`로 Artifact 게시(`icon: "video"`). Artifact에 올릴 파일은 작업 폴더나 스크래치패드 안에 있어야 한다. 알림 첫 문장에 "드라이브 업로드 실패, 아티팩트 링크로 대체"와 이유.
주의: Artifact 안에서는 다운로드 링크가 막혀 있어 영상 확인용이다. 원본 파일이 필요하면 별도 경로(15장) 결정이 필요하다.

**로컬 예약 실행 (운영 방식, 확정):** 운영 PC에서 돌고, 결과는 PC의 구글 드라이브 동기화 폴더에 저장, 알림은 Slack.
1. 저장 위치: `reels/config.json`의 `local_output_root`(현재 `D:/세븐스타즈 릴스`) 아래 `<시작일> 주` 폴더.
   본 렌더(4-7)는 `reels/out/<시작일>`에 하고, 검수가 끝나면 `node reels/deliver-local.js`로 MP4 7개 + txt 7개만 복사·확인한다(render-report.json·*_contact.jpg는 복사하지 않음).
   구글 드라이브 데스크톱 앱에서 이 폴더를 동기화 대상('내 컴퓨터' 폴더 추가)으로 지정하면 드라이브에 자동으로 올라간다.
   예약 실행 등록·권한 범위는 `reels/ROUTINES.md`.
   로그인이 안 돼 제작이 안 됐거나 중간에 끝나면 감시 작업(S4U, 금 14:30·토 12:00)이 Slack DM으로 알리고, 금·토에 로그인하면 따라잡기 작업이 이어서 만든다.
2. `local_output_root`가 비어 있거나 그 경로가 없으면(드라이브 앱 미설치·로그아웃) `reels/out/<시작일>`에 그대로 두고, 알림 첫 문장에 "드라이브 폴더 없음, PC의 reels/out에 저장"과 경로를 쓴다.
3. 알림(4-10)은 Slack `slack_send_message`로 `reels/config.json`의 `slack_channel`에 보낸다. 비어 있으면 알림을 건너뛰고 로그에만 남긴다.
4. DELIVERED에는 드라이브 폴더 경로를 적는다.

## 14. 이전에 겪은 문제와 해결법 (같은 실수 반복 금지)

| 증상 | 원인 | 해결 |
|---|---|---|
| 첫 슬라이드가 통째로 안 보이고 검은 화면 | CSS `.slide{display:none}`인데 코드가 `style.display==='none'`일 때만 block으로 바꿈(초기값은 빈 문자열) | 보일 때는 무조건 `display='block'` |
| 시작 0~1초 화면이 탁탁 깜빡임 | 모든 슬라이드에 visibility:hidden + will-change → GPU 레이어 동시 생성 / 자동재생 rAF가 캡처와 경쟁 | display:none 방식, 캡처 시 자동재생 끔(`capture=1`, `stopAnim`) |
| 시작 1초가 빈 화면 | 배경이 거의 검정 + 글자 opacity 0 | 0.5초 검은 커튼 페이드인 |
| 아래 줄 문구가 아주 작게 줄어듦 | width:100% 요소를 scrollWidth로 재면 항상 칸보다 넓다고 판단 | width:max-content로 원래 폭 측정 |
| 🍽 아이콘이 깨진 글자 | 변형 선택자(FE0F) 없는 이모지 | 완성형 이모지 사용 (`🍽️`) |
| 사진이 한 주에 두 번씩 겹침 | 날짜마다 주번호 계산(주 경계가 목요일) | 첫 대본 날짜로 한 번만 계산 |
| 4줄 훅이 2.3초 만에 넘어감 | 102BPM에서 4박(2.35초) 선택 | 2.55초 이상 되는 가장 짧은 박 단위 |
| 10월 영상에 캐럴 | 캐럴에 upbeat 태그도 있었음 | 캐럴은 christmas 태그만 |
| 마지막 장 맨 아래 줄이 검수 시트에 없음 | 검수 캡처 시점이 꼬리 구간 전 | 마지막 장은 영상 끝-50ms에 캡처 |
| "얼굴 안 보고" 문구 | 가림막 용도를 잘못 이해 | 사실 정리(1장) + 검증기 금지 표현 |
| 시스템 python에서 numpy/PIL 오류 | 클라우드 이미지의 python3 문제 | `python3.13` 사용 |
| OpenCV 얼굴 감지 없음 | cv2 빌드에 CascadeClassifier 없음 | 격자 미리보기로 수동 박스 |
| Artifact 게시 실패 | /tmp 파일은 게시 불가 | 스크래치패드로 복사 후 게시 |
| 스킬이 레포에 안 올라감 | `.claude/`가 gitignore | `reels/SKILL.md`에 둠 |
| 드라이브 업로드 불가 | 이 세션에 Drive 커넥터가 붙지 않음(`enabledInChat:false`) | 예약 설정에 커넥터 포함, 안 되면 대체 경로 |
